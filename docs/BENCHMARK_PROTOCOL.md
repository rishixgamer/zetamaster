# Default Benchmark Protocol and Caveats

## Public source references

- Original game UI: https://arithmetic.zetamac.com/
- Public form configuration summary: https://greasyfork.org/en/scripts/447518-options-for-arithmetic-zetamac-com/code
- Independent practice description: https://lamas-co.com/games/zetamac

Rules described publicly:
- Duration 120 seconds.
- Addition operands uniformly sampled *in our implementation* from integers [2,100] × [2,100].
- Subtraction generated by reversing an addition problem, e.g. `a+b − a = b`.
- Multiplication operands from [2,12] × [2,100].
- Division generated by reversing multiplication, e.g. `a×b ÷ a = b`.
- Four operations enabled, answers auto-submit upon matching, no pausing or skipping in benchmark.

**Audited 2026-10-17:** see [PARITY_AUDIT.md](./PARITY_AUDIT.md). Operation weights (uniform), operand mapping and draw order, inverse orientation (subtrahend and divisor are the first-range operand), absence of duplicate avoidance, and the answer-acceptance rule (`trim()` then exact string match) match the original client and are pinned by `tests/parity.test.js`. Remaining documented deviations: strict monotonic 120 000 ms cutoff (original ends on its next 1 s tick) and a different PRNG. Do not claim pixel, device, or individual score equivalence.

## Eligibility

For a completed run to count toward standard score progress:
1. `mode === 'benchmark'`.
2. Rules exactly match the immutable default preset and verified generator version.
3. The full 120-second interval elapses; manual termination is unverified.
4. No question skip, hint or adaptive weighting.
5. Score counts correctly solved questions, not keystroke errors. Unanswered final question is retained but does not count.

Practice scores are always labeled. Benchmark trend and target mastery use *only* standard runs.

## Target definition

Target **70+ consistently** is a personal goal operationalized as 8 or more standard scores ≥70 in the latest 10 completed standard runs. This is neither a quant hiring cutoff nor statistical certification of ability; it is a practical progress indicator.

## Benchmark QA checklist

- Verify all inclusive range boundaries and reverse-operation integrality.
- Compare independently generated operation frequencies against original if feasible.
- Test generator deterministic replay across browser and Node.
- Compare timer boundary behavior and focus/input semantics.
- Assert aborted sessions do not enter benchmark progress.
- Test that custom/quant/replay runs never contaminate standard counts.
- Record rule version with every run and migrate historical sessions explicitly when rules change.
